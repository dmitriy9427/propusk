# 02. Пароли

## Зачем что-то делать с паролем

Самый простой вариант — хранить пароль в базе как есть и сравнивать. Это катастрофа:

- базу утащат (утечки случаются у всех, от магазинов до банков) — и злоумышленник получит
  пароли всех пользователей. А люди используют один пароль везде;
- пароль увидит любой сотрудник с доступом к базе;
- пароль попадёт в бэкапы, логи, дампы для разработки.

**Правило: сервер вообще не должен знать пароль.** Он хранит то, что позволяет **проверить**
пароль, но не **восстановить** его.

## Шаг 1. Хеш — «отпечаток»

Хеш-функция превращает любые данные в строку фиксированной длины. В одну сторону — легко, обратно — невозможно.

```
SHA-256("весенний-ключ-2026") → "q3Lp…Xw"   (всегда одно и то же)
SHA-256("весенний-ключ-2027") → "M9aT…2k"   (совсем другое)
"q3Lp…Xw" → ???                              (обратного пути нет)
```

Проверка пароля: посчитать хеш введённого и сравнить с хешем в базе.

## Шаг 2. Почему обычного хеша мало

SHA-256 создан, чтобы быть **быстрым**: видеокарта считает миллиарды хешей в секунду.
Злоумышленник с утёкшей базой возьмёт словарь из миллиарда популярных паролей и за секунды
найдёт все совпадения.

Ещё хуже: у всех, у кого пароль `qwerty123`, одинаковый хеш. Достаточно один раз посчитать
таблицу «хеш → пароль» (так называемые радужные таблицы) и сверить с ней базу.

## Шаг 3. Соль и медленный хеш

**Соль** — случайные байты, свои у каждого пользователя. Хешируем `пароль + соль`:

```
Анна: соль a7f2…  PBKDF2("qwerty123" + a7f2…) → "Kd8…"
Борис: соль 19cc… PBKDF2("qwerty123" + 19cc…) → "pQ1…"   ← другой хеш при том же пароле
```

Готовые таблицы теперь бесполезны: перебирать придётся **каждого** пользователя отдельно.

**Медленный хеш** — функция, которая нарочно повторяет вычисление сотни тысяч раз. Для
человека 0,3 секунды при входе незаметны, а для перебора по словарю это в сотни тысяч раз дольше.

Специальные функции для паролей: **Argon2id** (лучший выбор сегодня), **scrypt**, **bcrypt**,
**PBKDF2**. В «Пропуске» — PBKDF2: он встроен в Web Crypto API и работает и в браузере, и в
Node без дополнительных библиотек.

## Как сделано в «Пропуске» — [server/lib/crypto.ts](../server/lib/crypto.ts)

```ts
export async function hashPassword(password: string, iterations = 600_000): Promise<string> {
  const salt = crypto.getRandomValues(new Uint8Array(16))        // ① соль — 16 случайных байт
  const hash = await pbkdf2(password, salt, iterations)           // ② 600 000 повторов SHA-256
  return `pbkdf2$${iterations}$${toBase64Url(salt)}$${hash}`      // ③ всё в одну строку
}
```

- ① `crypto.getRandomValues` — **криптостойкий** генератор. `Math.random()` для этого
  нельзя: его выход предсказуем.
- ② 600 000 повторов — рекомендация OWASP на 2023 год для PBKDF2-SHA256. Посмотрите на
  страницу входа: вход занимает около секунды — это и есть цена защиты.
- ③ В базе лежит строка вида `pbkdf2$600000$<соль>$<хеш>`. Число повторов хранится рядом:
  через пару лет его можно увеличить, а старые пароли продолжат проверяться со старым числом.

```ts
export async function verifyPassword(password: string, stored: string): Promise<boolean> {
  const [scheme, iterations, salt, expected] = stored.split('$')
  const actual = await pbkdf2(password, fromBase64Url(salt), Number(iterations))
  return safeEqual(actual, expected)                               // ④
}
```

④ `safeEqual` — сравнение **за постоянное время**:

```ts
export function safeEqual(a: string, b: string): boolean {
  if (a.length !== b.length) return false
  let diff = 0
  for (let i = 0; i < a.length; i++) diff |= a.charCodeAt(i) ^ b.charCodeAt(i)
  return diff === 0
}
```

Обычное `a === b` останавливается на первом несовпавшем символе. Тогда «совпало 5 символов»
отвечает чуть дольше, чем «совпал 1», и по времени ответа секрет можно угадывать посимвольно
(атака по времени, timing attack). Здесь цикл всегда проходит строку целиком.

## Вход: не подсказывать злоумышленнику

[server/routes/auth.ts](../server/routes/auth.ts), маршрут `POST /login`:

```ts
const INVALID = () => new ApiError(401, 'invalid-credentials', 'Неверная почта или пароль')

if (!user?.passwordHash) {
  dummyHash ??= hashPassword('dummy-password', iterations)
  await verifyPassword(password, await dummyHash)   // ① считаем хеш, даже если почты нет
  throw INVALID()
}
…
if (!(await verifyPassword(password, user.passwordHash))) {
  …
  throw INVALID()                                     // ② та же ошибка
}
```

**Перебор почт (user enumeration).** Если на «нет такой почты» ответить «Пользователь не
найден», а на неверный пароль — «Неверный пароль», злоумышленник по ответам составит список
зарегистрированных почт. Поэтому:

- ② в обоих случаях один и тот же текст и код;
- ① и одно и то же **время**: если почты нет, всё равно считаем PBKDF2 по «заглушке». Иначе
  «нет почты» отвечало бы мгновенно, а «неверный пароль» — через секунду.

Та же идея в регистрации: на уже занятую почту сервер отвечает тем же `201`, что при
успехе, а владельцу почты отправляет письмо «кто-то пытался зарегистрироваться». Так же
устроены «Вход по ссылке» и «Забыли пароль»: ответ одинаковый, есть такая почта или нет.

> Сказать честно «почта не подтверждена» или «аккаунт заблокирован» можно **после**
> верного пароля: человек уже доказал, что это его аккаунт.

## Блокировка после неудач

```ts
user.failedLogins++
const over = user.failedLogins - CONFIG.maxFailedLogins          // 5
if (over >= 0) user.lockedUntil = now + 30_000 * 2 ** over       // 30 с, 60 с, 120 с…
```

| Неудача № | Что происходит |
| --- | --- |
| 1–4 | «Неверная почта или пароль» |
| 5 | блокировка на 30 с |
| 6 | блокировка на 60 с |
| 7 | на 120 с… |

Удвоение (экспоненциальная пауза) делает перебор бессмысленным, но не запирает
настоящего человека, который ошибся пять раз, навсегда. Успешный вход сбрасывает счётчик.

Кроме того, есть общий лимит частоты ([server/lib/rate-limit.ts](../server/lib/rate-limit.ts)):
не больше 20 попыток входа и 5 писем на одну почту за 10 минут.

## Какой пароль считать хорошим

[shared/schemas.ts](../shared/schemas.ts) — правило **одно** для формы и сервера:

```ts
export const passwordSchema = z
  .string()
  .min(10, 'Не короче 10 символов')
  .refine((v) => !COMMON.includes(v.toLowerCase()), 'Этот пароль слишком распространён…')
  .refine((v) => new Set(v).size >= 5, 'Слишком однообразно…')
```

Нет требований «заглавная + цифра + символ». Такие правила дают `Password1!`, который
угадывают первым. Рекомендация NIST (американский институт стандартов): длина, проверка по
списку утёкших паролей, никаких принудительных составов и никакой обязательной смены раз в 90 дней.

`весенний ключ от дома` надёжнее, чем `P@ssw0rd!`, и его легче запомнить.
