# 08. Ссылки из писем

Три письма со ссылкой: **подтвердить почту**, **войти** (без пароля), **сбросить пароль**.
Устроены одинаково, отличаются сроком и последствиями.

| Ссылка | Срок | Что делает |
| --- | --- | --- |
| Подтвердить почту | 24 часа | разрешает вход по паролю |
| Войти по ссылке | 15 минут | создаёт сессию (а если есть 2FA — просит код) |
| Сбросить пароль | 15 минут | задаёт новый пароль и завершает **все** сессии |

## Пять правил ссылки — [server/core.ts](../server/core.ts)

```ts
export async function issueEmailToken(deps, userId, purpose, ttlSec) {
  const token = randomToken()                                                    // ① случайный, 256 бит
  for (const t of emailTokens) if (t.userId === userId && t.purpose === purpose && !t.usedAt) t.usedAt = now  // ② старые — недействительны
  emailTokens.push({ hash: await sha256(token), purpose, userId, expiresAt: now + ttlSec * 1000, usedAt: null })  // ③ в базе — хеш, ④ срок
  return token
}

export async function consumeEmailToken(deps, token, purpose) {
  const record = emailTokens.find((t) => t.hash === hash && t.purpose === purpose)
  if (!record || record.usedAt || record.expiresAt < now) throw invalid           // одна ошибка на все случаи
  record.usedAt = now                                                              // ⑤ одноразовая
  return user
}
```

1. **Случайный токен**, а не «id пользователя + время»: такое можно угадать.
2. **Новая ссылка отменяет старые.** Запросили сброс дважды — работает только последнее письмо.
3. **В базе — хеш.** Утекла база — ссылками не воспользоваться.
4. **Короткий срок.** Письма лежат в почте годами; старая ссылка не должна открывать аккаунт.
5. **Одноразовая.** Вторая попытка — «Ссылка недействительна».

`purpose` в проверке не даёт использовать ссылку подтверждения почты как ссылку входа.

## Убрать токен из адресной строки — [src/pages/auth/token-landing.tsx](../src/pages/auth/token-landing.tsx)

```ts
const [token] = useState(() => params.get('token') ?? '')        // запомнили
useEffect(() => {
  history.replaceState(null, '', location.pathname)               // и стёрли из адреса
}, [])
```

Пока токен в адресе, он попадает в историю браузера, в синхронизацию вкладок между
устройствами и в заголовок `Referer`, если на странице есть ссылка на другой сайт.

## Одноразовая ссылка и StrictMode

В режиме разработки React запускает эффекты **дважды**, чтобы найти эффекты без очистки.
Для одноразовой ссылки это ловушка: первый запуск использует токен, второй получит «Ссылка
недействительна», и человек увидит ошибку.

```ts
function useOnce(fn: () => void) {
  const done = useRef(false)
  useEffect(() => {
    if (done.current) return       // второй запуск — ничего не делать
    done.current = true
    fn()
  })
}
```

`useRef` переживает двойной запуск, поэтому вторая попытка видит `done.current === true`.

## Сброс пароля завершает все сессии

```ts
user.passwordHash = await hashPassword(password)
revokeAllSessions(deps, user.id, 'Пароль сброшен')   // все устройства — на выход
sendMail(deps, user.email, 'Пароль изменён', …)       // и письмо владельцу
```

Пароль часто сбрасывают **потому что** его украли. Если оставить сессии, вор останется в
аккаунте и после сброса.
